### tests/mgba-socket-client.test.ts (8 tests) -> crates/mgba/src/protocol.rs + ipc_transport.rs (29 tests)
- formats messages with/without args          -> format_message_without_args, format_message_with_one_arg, format_message_with_multiple_args, format_message_string_args
- parses success/error/plain responses        -> covered via response_to_string family in ipc_transport.rs (memory_data_*, current_frame_response_*, error_response_prefixed_with_error)
- splits partial TCP reads                    -> NOT PORTED. Justification: Rust architecture replaces the legacy mGBA TCP socket
                                                  with Unix-domain IPC; tokio::io read_exact handles fragmentation.
                                                  Coverage exists at the framing layer: ipc/transport.rs::larger_payload_roundtrip
                                                  and command_roundtrip exercise large/multi-fragment payloads end-to-end.
- round-trip through mock TCP server          -> ipc/transport.rs::command_roundtrip (equivalent over Unix IPC)
- serializes concurrent requests              -> mgba/scheduler.rs::prioritizes_control_and_memory_over_frame_capture_when_pending
- retries one in-flight request               -> NOT PORTED. Justification: the legacy mGBA TCP socket's transient-close retry
                                                  is replaced by Worker process supervision + IPC reconnect; not a per-request retry
                                                  semantic in the Rust path.
- reconnects on next send                     -> NOT PORTED. Justification: same as above; reconnect lives at ProcessBackend
                                                  health-check level rather than inside MgbaSocketClient.

### tests/frame-capture.test.ts (4 tests) -> NOT PORTED
Justification: The FrameCapture class (sharp PNG decode, repeated cached delta when source capture is in flight) does
not exist in the Rust port. Frame ingest uses libretro's video_refresh callback and is pushed into FrameHub directly.
The behaviors that DO have analogs are covered:
- keyframe vs delta cadence and cached keyframe -> streaming/broadcast.rs::keyframe_cached_on_push +
  protocol.rs::encode_decode_roundtrip + protocol.rs::delta_encoding_detects_changed_tiles
- causality metadata attaching to frames        -> streaming/protocol.rs::metadata_roundtrip_with_causality
- input log lifecycle                           -> streaming/input_log.rs (4 tests)

### tests/dashboard-broadcast.test.ts (10 tests) -> partially ported
- "encodes raw-tile stream frames" with protocol metadata -> streaming/protocol.rs::encode_decode_roundtrip,
                                                              encode_known_frame_matches_wire_format_spec
- "drops frames for clients over backpressure"           -> NOT PORTED. Justification: the Rust path uses a
                                                              watch::Receiver per subscriber; backpressure naturally drops via
                                                              borrow_and_update semantics rather than via a bufferedAmount probe.
                                                              The drop behavior is covered by streaming/frame_hub.rs::backpressure_drops_old_frames.
- "replays latest keyframes to new clients"              -> covered by broadcast.rs flow exercised in
                                                              gateway integration tests (tests/integration.rs).
- "routes per-instance frames to matching token"         -> covered by gateway/lib.rs::cross_session_token_fails_before_handler
                                                              (per-session access enforced before stream subscribe)
- "closes malformed session paths without throwing"      -> NOT PORTED. Justification: Axum router rejects invalid path
                                                              segments with 404 automatically; no panic-resistance test needed
                                                              since the framework guarantees this.
- "suppresses deltas after dropped stateful frame"       -> covered structurally by broadcast.rs recovery_mode handling;
                                                              not behaviorally tested because it requires running a real WS
                                                              and forcing backpressure mid-stream.
- "marks dropped cached keyframe replay for recovery"    -> same justification as above
- "ignores oversized viewer controls before parsing"     -> streaming/protocol.rs::viewer_control_too_large_rejected
- "transports realtime input-log events"                 -> covered by gateway/lib.rs input_log_ws handler +
                                                              streaming/input_log.rs::subscribe_receives_live_events
- "accepts throttled keyframe requests"                  -> covered structurally by broadcast.rs KEYFRAME_THROTTLE_MS;
                                                              behavior requires real WS client to assert.

### tests/capture-paths.test.ts -> NOT PORTED (intentional)
Justification (from task brief): no capture files in Rust port. The Rust pipeline streams frames in-memory from
libretro via FrameHub; there are no host-side bind-mounted screenshot files.

### tests/docker-driver.test.ts -> NOT PORTED (intentional)
Justification (from task brief): Rust uses ProcessBackend (child process workers) instead of a Docker driver.
ProcessBackend lifecycle is covered by instances/lib.rs::process_backend_spawn_and_kill and the manager-level
create/destroy/max-instances tests with a FakeBackend.

### tests/benchmark-report.test.ts -> NOT PORTED (out of scope for task 25)
Justification (from task brief): scoring logic is not yet ported; orthogonal to the test suite gap analysis.
